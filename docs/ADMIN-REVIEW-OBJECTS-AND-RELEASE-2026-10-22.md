# 管理后台逐对象审阅与一次审批发布

本说明描述管理员工作台代码所实施的审阅与发布路径。代码合并或 Worker 部署前，线上后台不会获得这些更新。

## 审阅对象与采集范围

- 批次先显示本次采集对象列表，可按名称、简称、届次或 ID 搜索，并按期刊/会议、待处理/已处理/失败筛选。
- 一个会议载体下的届次、主会、晚稿和附属征稿按正式实体 ID 分开显示；专题征稿显示其期刊父项。点击一个对象后，只显示该对象的审阅细节。
- 对象的接受、修正、拒绝可分别保存为后台草稿。切换对象前会先保存当前对象；提交整批取舍时，未明确接受的事实会写入审计为默认拒绝。
- 手工样本、到期来源检查和复用既有证据重新整理会标示为不同的运行类型。计数来自采集结果；手工样本不会表示全目录覆盖。复用既有证据时，检查数为 0，不伪装为再次抓取。
- 历史批次若未保存运行范围，只显示“范围未记录”，不推断其他来源无变化。

## 唯一性边界

自动数据路径只允许更新当前目录中的稳定 ID。应用前按目录中的实体类型、父载体、届次和正式数据文件重新核对。名称译文、别名或域名相近都不会触发实体合并；共用网站域名也不会单独构成身份依据。

结构化事实优先沿用同一官网来源锚点和官方标题层级生成的稳定编号，不依赖中文或 Copilot 候选标题。若旧目录已有相同官网锚点/层级，会沿用旧编号；相同类别且结构化值或原文引句完全相同的事实不重复新增。不同来源或不同引文中的冲突会保留为待审候选。

此规则不是自动发现新刊物、新会议或自动合并实体的功能。多个 ISSN/eISSN 版本、同域名出版平台、同名不同刊、旧域名迁移等仍需维护者依据官方身份资料人工核对；本轮自动路径不编辑 ID、名称、ISSN、分类或父载体关系。

## 一次审批发布

1. 管理员在后台逐对象保存候选取舍，可只处理希望接受或修正的内容。
2. 点击“提交取舍并自动生成数据 PR”。未明确接受的候选自动记录为拒绝；若没有任何已接受或修正项，则批次被拒绝、来源解锁且不创建 PR。否则可信主线工作流自动生成受限数据 PR 并运行目录检查、测试和构建。
3. 后台显示最终 PR 文件、完整补丁、SHA 和检查状态。只有 PR 的改动文件与接受对象的数据文件集合完全一致、补丁完整且必需检查通过时，才开放发布按钮。
4. 点击一次“批准并发布这些更新”后，Worker 重新核验当前管理员权限、PR 作者、最终 SHA、差异摘要和检查结果；以该管理员实际 GitHub 身份对最终 SHA 提交 APPROVE，再调用标准合并 API。仓库的分支保护和必需检查继续执行。
5. 合并、Pages 部署和日历/网站更新分别记录状态。邮件仅提醒；未配置或发送失败不会阻止候选审阅或审批。

候选草稿操作不等于正式发布批准。后台管理员无需去 GitHub 对同一数据版本重复操作。代码、工作流、权限、配置、目录身份以及数据库迁移仍必须走正常开发 PR。

## 自动数据 PR 限制

- 只允许修改既有普通文件：`data/venues/<方向>/<稳定ID>.yml` 与 `data/calls/<年份或rolling>/<稳定ID>.yml`。
- PR 必须与已接受候选产生的精确文件集合完全一致。仅修改，不允许新增、删除、重命名、路径穿越、符号链接、子模块或非 YAML 文件。
- 单次最多 20 个实体/文件；单文件最多 256 KiB；文件总量最多 1 MiB。
- 仅保存已定义的 `officialSections` 字段、经证据支持的内容和已绑定稳定节点的日期更新。修正不可改写稳定分段 ID、官网 URL 或引文证据；不允许删除分段。
- 最终版本以 PR 最终 SHA 和 GitHub 完整文件差异摘要绑定。差异不可完整读取、内容变更、文件集合不符、PR 作者与当前审批人相同或必需检查失败时，发布按钮不能通过。

## 本地验收范围

自动测试覆盖对象草稿持久化、受限修正、作者自批拦截、PR 最终文件/路径白名单、来源唯一事实去重、冲突保留、稳定事实编号、符号链接/新增/删除/重命名拦截，以及运行范围标记。

浏览器的多对象真实交互、生产 Worker 部署、实际 GitHub 分支保护设置和一条真实数据发布仍需在此 PR 合并及后台部署后验收。本任务不改变生产开关、不启动定时采集、不执行真实数据审批或合并。
